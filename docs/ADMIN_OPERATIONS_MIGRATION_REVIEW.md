## Prepared route scope

Eight previously placeholder routes now use protected real API contracts: compose/logs, editable download classifications, saved seat plans, both carry-forward aliases, transport assignment/reporting and subject-session recording/reporting. Tables, forms, reference search/paging, optimistic edits where supported, explicit migration gates, page CSV and escaped page printing are prepared. A disabled form does not count as a working persistence workflow. The readiness ledger marks all eight as partial and migration-blocked.

Download types classify existing secured download materials; existing file upload/download protection is retained. Seat assignment is explicit, not automatic optimization. Transport stores vehicles, optional staff driver, capacity, pickup and dated assignments; it does not implement GPS or fare billing. Attendance supports explicit per-student session marks and corrections, not inferred presence. Printing opens the browser print dialog for up to 20 displayed persisted rows; physical output is not certified. These boundaries must remain visible during demonstration and acceptance.

Provider configuration remains runtime-owned: existing SMTP settings or `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM`. Sender profile storage in the configuration draft does not activate a provider. Delivery acknowledgement semantics follow [Nodemailer](https://nodemailer.com/usage) and the [Twilio Message resource](https://www.twilio.com/docs/messaging/api/message-resource).
